# DS3 기준 전투 접촉·카메라 검증 (2026-09-29)

## 원작 근거와 Battle 구현의 경계

- [Souls Modding TAE](https://www.soulsmodding.com/doku.php?id=format%3Atae)는 애니메이션 시간대에 공격, 회피 무적, 가드 등 이벤트를 둔다. [BehaviorParam 설명](https://soulsmodding.com/doku.php?id=des-refmat%3Aparam%3Abehaviorparam)에 따르면 공격 이벤트의 ID가 BehaviorParam을 거쳐 AtkParam_Npc에 연결된다.
- Battle은 이 **시간 이벤트 → 공격 속성 → 메시와 벽을 확인하는 접촉 추적 → 피해·반응** 구조를 UE의 보스 액션 Data Asset, `OpenActionImpact`, 소켓 이동 스윕, 피격 메시로 구현한다. Crunch는 DS3 보스의 원본 스켈레톤·TAE·AtkParam이 아니므로 아래 초·cm 값은 Crunch 몽타주를 PIE로 측정해 맞춘 Battle 값이다.
- 카메라 기본 데이터 4m 자유 시점, 6m 락온, 수직 FOV 43도 등은 설치된 DS3 `LOCK_CAM_PARAM_ST` 행을 읽어 이전에 적용했다. 행의 필드 구조는 [Paramdex](https://github.com/soulsmods/Paramdex/blob/master/DS3/Defs/LOCK_CAM_PARAM_ST.xml)와 대조했다. 특정 DS3 보스에 어느 행이 연결되는지는 입증되지 않았으며, Battle의 근접 보정은 별도 설계값이다.

## 보스 공격 판정 수정

각 패턴의 실제 몽타주를 재생하면서 주먹 소켓과 플레이어 피격 메시를 시간별로 추적했다. 판정이 열렸는지와 실제 체력 감소를 새 PIE 세션에서 검증했다. 데이터 경로는 `/Game/BossArena/Boss/AI/Actions/`이다.

| 패턴 | 바꾼 값 | 확인한 결과 |
| --- | --- | --- |
| 왼손 | 판정 시작 0.375→0.95초, 지속 0.35→0.22초 | 285cm에서 110 피해. 기존 판정은 주먹이 닿기 전에 닫혔다. |
| 오른손 | 반경 110→180cm | 285cm에서 110 피해. 기존 반경은 플레이어 피격 메시까지 닿지 않았다. |
| 어퍼컷 | 시작 0.889→0.29초, 지속 0.188→0.17초 | 285cm에서 110 피해. 실제 손 접촉은 약 0.30~0.36초였다. |
| 휩쓸기 | 변경 없음 | 285cm에서 160 피해를 확인했다. |
| 잽→잽→훅 | 세 시작 시점 0.725/2.239/4.244→1.30/2.22/4.28초, 반경 110→220cm, 지속 0.188→0.14초 | 285cm에서 40+40+65=145 피해. 세 타의 각 손 경로를 따로 측정했다. |

| 돌진 | 타격 소켓 `hand_r`→`hand_l`, 반경 110→130cm | 600cm에서 약 340cm 전진한 뒤 160 피해. 몽타주에서 실제로 플레이어를 가로지르는 손은 왼손이었다. |

`BP_Boss_Crunch.RequestCombatAction`은 수동 패턴 요청 직전에 플레이어까지의 수평 거리를 갱신한다. 이전에는 `UtilityDistance=0`이라 돌진 잔여거리가 0으로 계산되어 테스트와 수동 미리보기에서 보스가 움직이지 않았다. 블루프린트 컴파일 후 배치된 보스의 Visibility 채널 충돌 응답을 다시 적용하고 레벨을 저장했다.

**검증:** 실제 몽타주 접촉: 왼손 `20260929T014947Z-3F3FAD12`, 오른손 `20260929T015802Z-4599A632`, 어퍼컷 `20260929T015804Z-A02CFECC`, 연계 `20260929T015808Z-9EC220A3`, 가드 브레이크 `20260929T015814Z-30AD567D`, 돌진 `20260929T021335Z-766A7A63`. 보스가 플레이어 검격에 맞을 때의 피해·방향별 반응, 진행 중 공격 유지, 벽 가림, 구르기 무적, 중복 적중은 `20260929T021414Z-BFFC54D2`(38개 assertion)와 `20260929T021432Z-B78B13E1`(25개 assertion)에서 통과했다.

## 카메라·조작 검증

- 락온 정지 상태 3m/6m/10m에서 보스 머리와 발이 화면 안에 들어왔다. 공격 중 락온도 보스 전신과 플레이어가 함께 보였다 (`20260929T020351Z-21031188`).
- 자유 시점의 큰 가림 원인은 화면 오른쪽 약 1/3을 덮던 `WBP_BossAIDebug` 텔레메트리였다. 패널을 좌상단에 0.68배로 배치해 전투 시야를 확보했다. 자유 시점 3m 캡처 `20260929T020457Z-7E1A1E53-camera-free-300.png`에서 보스가 패널 뒤에 가려지지 않는 것을 확인했다.
- SpringArm의 벽 충돌은 403→181cm로 카메라를 당겼다가 장애물 제거 후 403cm로 복원했다 (`20260929T020620Z-8357A43C`). Space 짧게 누르는 medium roll의 이동·벽 정지, 길게 누르는 달리기의 락온 일시 해제·복귀 검사는 각각 `20260929T020700Z-1180378E`, `20260929T020655Z-3A221636`에서 통과했다.

## 조정 범위

원작 DS3의 이벤트/파라미터 **구조**와 확인된 카메라 행을 기준으로 삼았다. Crunch의 110~220cm 판정 반경과 타격 시점, 텔레메트리 배치, 큰 보스 근접 보정은 Battle 고유값이다. 일부 자유 시점에서는 보스를 매우 가까이 따라가면 몸이 화면 가장자리에 걸릴 수 있다. 락온은 전신 구도를 제공하며, 자유 시점은 사용자가 카메라를 돌리는 조작을 유지한다.
