# DS3 플레이어 조작·카메라 참조 사양과 Battle 적용

2026-09-29. 수치의 출처를 **DS3 게임 파일에서 읽은 카메라 값**, **사용자가 준 조작 참고 텍스트**, **Battle용 조정값**으로 구분한다. 현재 Battle의 조작키는 유지한다.

## 1. 출처와 해석 범위

- Steam 설치본 `DARK SOULS III/Game/Data0.bdt`의 `LOCK_CAM_PARAM_ST` 141행을 읽기 전용으로 추출했다. 원본 파일 SHA-256: `955016ab940f0e3526b7ef9e29cff7b498e032939023b50b5d5a172832582b87`. 추출 코드: `Tools/ReadDS3Camera.py`; 로컬 전체 추출: `Saved/VibeUE/ds3-camera-rows.json`.
- 필드 이름과 형식: [soulsmods/Paramdex의 DS3 LOCK_CAM_PARAM_ST 정의](https://github.com/soulsmods/Paramdex/blob/master/DS3/Defs/LOCK_CAM_PARAM_ST.xml). [Souls Modding의 TAE 설명](https://soulsmodding.com/doku.php?id=format:tae), [DSAnimStudio](https://github.com/Meowmaritus/DSAnimStudio)는 애니메이션 이벤트와 취소·무적·추적 구간을 설계하는 구조적 참고 자료다.
- 카메라 행에는 대상 이름이 들어 있지 않다. 현재는 기본 행 0과 군다의 모델 번호에 대응하는 행 5110을 선택했다. 군다 NPC의 강제 카메라 ID는 -1이며, 5110의 이벤트 연결은 직접 추출하지 않았다. 모델 번호에 따른 행 선택은 추론이다.
- 첨부된 R1의 `0.100`, `0.300`, `0.470` 등의 시각은 설명용 예시다. 원본 `c0000` TAE와 루트 모션은 아직 추출하지 않았으므로 Battle 공격 시간을 원작 실측치라고 부르지 않는다.

## 2. 현재 카메라 설정

최신 구현은 사용자의 멀미·줌 변화 피드백을 반영한 [고정 거리 카메라](stable_lock_camera.md)를 따른다. 자유/락온 모두 650cm/182cm, 수직 화각 43도다. 카메라는 안정된 보스 기준점을, 표식은 실제 몸통 소켓을 사용한다. 650cm는 Battle 전용 조정값이다. 이전 DS3 행 0/5110의 400/550cm 참조값과 구현 이력은 [카메라·락온 적용 결과](ds3_camera_current.md)에 남겼다. 근접 추가 거리 보정은 계속 제외한다.

5110 행의 원작 이벤트 연결, NPC 거리 필드와의 조합, 보간·충돌 내부식은 직접 검증되지 않았다. 데이터 값과 UE에서 재현한 규칙은 최신 문서에서 구분했다.

### 질주 카메라 전환 (2026-09-29)

락온 상태에서 실제 Space 홀드 트리거가 발동하면 `LockOnTarget`을 저장하고 해제한다. 표식도 함께 숨긴다. 이때 카메라 거리와 월드 피벗 높이는 직전 프로필을 유지해 상태 전환 때문에 당겨지지 않는다. 달리기 종료 시 같은 타깃에 복귀하되, 죽었거나 거리 밖이면 저장 타깃을 폐기한다. 실제 MMB/Space 입력 및 표식·화각·거리·복귀 검사는 `20260929T045925Z-8FADABBD`, 복귀 거리 조건 검사는 `20260929T050109Z-07C88C9B`에서 통과했다. 이 프로필 유지 방식은 Battle에서 재현한 전환 규칙이다.

공격 판정, 회전, 구르기 취소, 연계 입력, 회복 종료는 서로 다른 구간이다. 공격 몽타주 4개에 다섯 종류의 실제 `AnimNotify`를 배치했고, 판정·취소·연계 타이머는 실행 체인에서 제외했다. 구르기의 캡슐 `SetActorLocation` 체인도 제외하고 기존 Kubold 클립의 루트 키가 이동을 구동한다. DS3 원본 구르기 클립과 TAE를 복제한 것은 아니다.

### 판정 표시와 4타 지연 개선 (2026-09-29)

공격 재생 배율 1.1→1.4, 연계·종료 이벤트를 앞당겼다. 히트 스톱은 실제 70→45ms로 줄이고 타격 이펙트 크기를 0.28로 조절했다. Crunch는 주황, 검은 파랑으로 실제 공격 검사 범위를 표시하며 접촉 지점에는 짧게 녹색 표시를 남긴다. 상시 몸통 캡슐은 숨겼다. 최신 계측·검증은 [공격 판정 표시와 4타 조작감 조정](combat_readability_polish.md)을 따른다.

## 6. 2026-09-29 기능 검증

- 8방향 락온 구르기는 모두 약 320cm 이동하고 방향 정렬 0.94 이상을 만족했다 (`20260929T011134Z-E3EBC83C`, 34/34). 기존 구르기 상태·무적·입력 예약 검사도 35/35, 이동 충돌 검사 15/15 통과.
- 공격 몽타주 타이머를 우회한 상태에서 판정 창 열림·닫힘과 구르기 취소 이벤트를 PIE로 확인했다 (`20260929T013015Z-7C31A29F`). 4타 연계·가드·달리기·점프·구르기 종합 검사 35/35 통과 (`20260929T013123Z-6B81D153`).
- 카메라 300cm 근접 캡처: `Saved/VibeUE/Scenarios/20260929T011846Z-0623324B-locked-boss-at-300cm.png`. 초반 추적 후 공격 방향 고정 검사 통과 (`20260929T013112Z-49747CF8`).
- 이 검증은 **Battle에서 실제로 동작하는 구조**를 증명한다. DS3 원본의 모든 프레임 값·카메라 내부 보간식·TAE/HKS 우선순위까지 일치한다는 뜻은 아니다.

## 5. 변경·검증 기록

- 구현 스크립트: `Tools/PolishDS3CameraControl.py`의 `apply()`를 Unreal Python에서 PIE 종료 후 호출한다. 플레이어 블루프린트와 4개 공격 시퀀스의 변경 전 백업은 `/Game/BossArena/Backup/*_PreDS3Camera_20260929`. 루트 키 25% 변환은 이번에 백업을 만든 후 Editor Python 컨트롤러로 한 번 적용했으며 `apply()`는 저장된 시퀀스를 다시 변환하지 않는다.
- 검증 스크립트: `Tools/TestDS3CameraControl.py`와 기존 `Tools/TestSwordShield.py`, `Tools/TestSoulsHits.py`.
- PIE: 자유 카메라/공격 궤적 10개 (`20260928T162801Z-7BDD9005`), 락온·가드 홀드 12개 (`20260928T163252Z-8EA4ED71`), 분리 취소 창 10개 (`20260928T164119Z-389B14B2`), 초반 추적·후반 고정 9개 (`20260928T164255Z-9607D4D6`), 락온 획득·해제 거리 13개 (`20260928T164841Z-11A46CE3`), 기존 공격·피격·구르기 21개 (`20260928T163734Z-264B07C6`), 락온 달리기 15개 (`20260928T163156Z-46E56F64`), 칼/보스 판정 38개 (`20260928T164334Z-EC0C066D`). 총 128개 검사 통과. 모든 시나리오는 `LogScript: Warning` 부재도 검사했다.
