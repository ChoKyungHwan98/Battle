# Crunch 3타 연계: 후딜 중 늦은 피격 수정

2026-10-04. 대상은 `/Game/BossArena/Boss/AI/Actions/DA_Attack_Combo`의 `잽 → 잽 → 훅` 행동이다.

## 문제와 재현

기존 `ActiveSeconds=0.14`, `TotalSeconds≈7.563`에서는 HFSM이 마지막 주먹 직후 `Attack.Recovery`로 넘어갔지만 물리 손 판정 `bPhysicalStrikeOpen`이 약 0.5초 더 열려 있었다. `TestBossPunishWindow.py`의 최초 PIE에서는 Recovery 시작 6.392초, 마지막 열린 판정 샘플 6.907초였다. 더 중요한 실제 피해 시험에서 세 번째 주먹을 피한 플레이어를 Recovery 시작 후 손 위치에 놓자 **65 피해**가 발생했다 (`20261004T094113Z-5ED5D21E`). 후딜을 반격 기회라고 설명하는 기획과 충돌한다.

## 수정

손 판정 자체를 잘라 마지막 타격을 잃지 않도록, 액션 데이터의 타격 상태를 `ActiveSeconds=0.95`로 늘렸다. 이는 연계의 각 주먹 사이에도 적용되지만, 다음 주먹은 기존 `ImpactTimes`의 절대 시각을 기준으로 이어진다. `TotalSeconds`는 실제 플레이어 검 3타 시간을 보고 최종 **8.95초**로 조정했다. 주먹의 모션, 손 추적 방식, 피해량은 바꾸지 않았다.

## 검증 결과와 해석

| 시험 | 결과 | 의미 |
| --- | --- | --- |
| Recovery 중 손 위치에 플레이어 진입 | 판정 닫힘, 추가 피해 0 (`20261004T095101Z-7B036012`) | 이전 65 피해 재현 경로가 막혔다. |
| 실제 입력으로 검 반격 | 보스가 빗나간 뒤 190cm에 플레이어를 놓고 키 입력을 연결하자, 12 피해씩 **3타가 Recovery 안에 적중** (`20261004T095015Z-21CB8DED`) | 가까이 남은 조건에서 3타 보상이 가능하다. 네 번째는 Ready 이후였다. |
| 물리 창/상태 기록 | Recovery 동안 회전·위치 이동 0, 손 판정 닫힘. 최종 화면 캡처와 타이밍 시험 통과 (`20261004T095140Z-8F3B0345`) | HFSM이 반격 구간 동안 새 공격을 고르지 않았다. |

플레이어 검의 실제 타격 간격은 기존 측정에서 약 0.48~0.50초였고, 세 번째 피해는 첫 입력 약 1.26초 뒤였다. 따라서 처음 가정한 ‘0.6초에 3타’는 현재 모션의 실측값과 맞지 않는다. 8.7초 시험에서는 3타가 한 번 Recovery 안에 들고 한 번은 Ready 복귀와 같은 샘플에 걸렸다. 8.95초는 이 간격을 고려한 **첫 플레이테스트 값**이다.

시험은 회피 모션의 성공을 증명하지 않는다. 자동화는 보스가 빗나간 뒤 플레이어를 근접 위치로 재배치하고 실제 공격 키를 눌렀다. **실제 좌·우·뒤 회피로 같은 위치에 남을 수 있는지**, 세 번째 타격을 넣고 다시 피할 수 있는지, 길어진 회복 자세가 자연스러운지는 사람의 조작 영상으로 확인해야 한다. 첫 주먹의 짧은 판정 창은 낮은 PIE 프레임에서 한두 번 건너뛴 관측이 있어 전 방향 접촉 시험도 남아 있다.
