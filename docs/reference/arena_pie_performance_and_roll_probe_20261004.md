# 아레나 PIE 프레임과 회피·반격 검증 기록

2026-10-04. 이 기록은 **제출 영상의 전투 경험을 검증하기 위한 진단**이다. 에셋이나 레벨 값은 바꾸지 않았고, 화면 숨김과 그래픽 옵션은 PIE에서만 잠시 적용했다.

## 왜 조사했나

3타 연계의 첫 손 판정이 자동 시험에서 간헐적으로 빠졌다. 손 판정 창은 짧은데, 이번 무인 PIE 화면은 대략 15fps였다. 이때 한 프레임은 약 67ms이므로 손이 닿는 짧은 순간을 샘플링하기 어렵다. **낮은 프레임과 판정 누락의 인과관계는 아직 입증되지 않았다.** 보이는 주먹과 실제 손 소켓, 판정 창을 같은 시간축에서 다시 재야 한다.

숫자는 고정 카메라·장시간 통계가 아니라 개별 시점의 `PerformanceService.frame_timing()`이다. 애니메이션 자세, 카메라, 드라이버 상태에 따라 달라질 수 있다. 따라서 현재 근거로 메시를 교체하거나 주먹 판정을 넓히지 않는다. 렌더 비용을 줄일 때는 보스의 스켈레탈 메시·머티리얼·그림자와 플레이어를 대상으로 같은 시점에서 여러 번 재측정한다. Unreal Insights 추적 시작은 이번 세션에서 실패했으므로 세부 원인은 미확정이다.

## 실제 회피→반격 시험 시도

기존 3타 검 입력 시험은 보스가 빗나간 뒤 플레이어를 근접 위치로 **재배치**했다. 이를 대신할 실제 이동키+Space 회피 시험을 무인 PIE에서 두 번 시도했다.

1. 첫 실행은 에디터 백그라운드 제한으로 최대 약 3fps였다. 짧은 회피 입력을 판단할 수 없는 환경이라 결과를 폐기했다 (`20261004T101558Z-5583C2A7`).
2. 제한을 해제한 실행에서는 이동키가 적용됐고 보스 Recovery 중 플레이어 검 피해 2회가 기록됐다. 그러나 Space 입력 뒤 플레이어의 `Dodge` 상태와 `DodgeTimeNewest` 변화는 없었다. **회피 성공 사례가 아니다** (`20261004T101636Z-2E304001`).
3. 입력 경로를 분리하려고 기존 단독 회피 시나리오를 실행했으나, 이 무인 PIE에서는 플레이어가 생성되지 않아 시험 설정 자체가 실패했다 (`20261004T101754Z-5E27102B`). 이것도 게임의 회피 기능 실패를 뜻하지 않는다.

다음 검증은 플레이어 생성 위치를 명시한 PIE 시나리오에서 진행한다. 회피 입력은 관찰용 Tick 콜백이 아니라 시나리오의 키 입력 단계로 보내고, **회피 상태 진입 → 무적 시작/끝 → 보스 마지막 손 판정 종료 → 근접 위치 → Recovery 중 실제 검 2–3타**를 한 기록에 남긴다. 이 순서가 통과하기 전에는 ‘회피하면 3타 보장’을 제출 성과로 쓰지 않는다. 사람 조작 영상에서도 같은 순서를 눈으로 확인한다.
