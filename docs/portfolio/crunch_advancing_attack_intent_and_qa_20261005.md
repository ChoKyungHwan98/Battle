# 전진 공격의 의도 정정과 플레이 QA 기록

## 지금 확인한 기획 의도

원하는 경험은 **보스가 걸음을 공격의 리듬으로 사용해서 압박하는 전투**다.

플레이어가 조금 떨어져 있을 때, 보스가 공격을 선택하고 **한 발 쿵 → 다음 발과 함께 주먹 쿵 → 후딜**로 이어진다. 첫발부터 공격 준비 동작이다. 플레이어는 이 걸음과 팔의 움직임을 보고 회피할 순간을 판단한다. 보스는 제자리 공격과 전진 공격을 모두 사용할 수 있어야 한다.

앞서 적용한 접근 기능은 ‘이동해서 공격 거리로 들어온 다음 공격을 새로 선택’하는 방식이었다. 접근 속도와 정지 거리를 바꿨지만, 플레이어가 보는 반복은 여전히 ‘다가오기 → 멈추기 → 때리기’에 가깝다. 이것은 이번에 확인한 의도를 충분히 반영하지 못했다.

군다를 예로 든 사용자의 설명은 ‘공격과 이동이 하나의 동작으로 읽히는 경험’으로 이해했다. 이 문서는 군다 원본의 내부 구현이나 수치를 확인했다는 주장이 아니다.

이번 작업은 **QA 기록만 추가**했다. 전진 공격 패턴, 기존 접근 동작, 점수와 공격 타이밍은 이번에 수정하지 않았다.

## 다음 설계에서 세 기능의 역할

- **Utility AI:** 지금 제자리에서 때릴지, 한두 발 디디며 때릴지, 크게 거리를 좁힐지 후보 중 하나를 고른다. 가까우면 항상 같은 주먹을 반복하도록 만들지 않는다.
- **HFSM:** 전진 공격을 골랐다면 ‘첫발부터 공격 준비 → 타격 → 후딜’이라는 한 패턴을 진행한다. 도중에 매번 접근 행동으로 돌아가거나 새 공격을 고르지 않게 한다. 방향 수정과 이동을 허용할 구간도 패턴에 맞춰 정한다.
- **GOAP:** 공격이 가능한 위치까지 가는 과정이 따로 필요할 때 그 과정을 연결한다. 공격에 포함된 첫발과 둘째 발을 일반 접근으로 대신하지 않는다.

다음 구현 전에는 사용할 발 디딤 모션, 주먹이 나가는 시점, 앞으로 이동할 거리, 제자리 공격과의 구분을 함께 정리해야 한다. 이 항목은 아직 구현 완료가 아니다.

## 직접 플레이하고 기록 남기기

1. 평소처럼 `Lvl_Arena_01`에서 Play한다.
2. 어색한 상황을 재현한다. 가능하면 ‘대략 시작 후 몇 초, 무엇을 했을 때’를 기억한다.
3. Stop한 뒤 **“방금 플레이 로그 봐줘. ○○가 이상했어”**라고 말한다.

별도의 기록 버튼이나 파일 전송은 필요 없다. 보스의 전투 시작 함수가 QA 타이머를 시작한다. `Lvl_BossMotionLab`도 같은 보스 함수를 사용하므로 수동 공격의 상태·판정 기록이 연결되어 있다. 모션 랩에서는 자율 선택을 억제하므로 후보와 선택 기록의 의미가 일반 전투와 다르다. 실제 기록 생성 확인은 사용자의 플레이 후 진행한다.

화면의 움직임이 어색하면 짧은 영상도 도움이 된다. 로그만으로는 발이 미끄러져 보이는지, 모션 연결이 자연스러운지 판단할 수 없다.

## 무엇이 기록되는가

| 기록 | 확인하려는 문제 |
|---|---|
| 선택 후보의 최종 점수와 제외 이유 | 특정 공격이 선택되지 않는 이유 |
| 실제 선택, 상태 변화, 타격 번호 | 접근과 같은 공격이 반복되는지, 공격이 실제 시작됐는지 |
| 위치·속도·방향, 이동 목표, 공격 발 디딤 진행 | 어디서 멈췄고 언제 전진했는지 |
| 팔 판정 시작·종료, 접촉 전달 | 어느 타격 구간에 팔 접촉이 처리됐는지 |
| 플레이어 HP·스태미나·속도·무적·가드 | 피해와 방어·회피 상태의 관계 |
| 회피 허용, 가드 시작·해제, HP 감소, 스태미나 반환 | 가드 후 회피 속도와 반환 문제를 추적 |

기본 표본은 **0.2초 간격**이다. 선택·상태·판정·피해 등의 이벤트는 그 함수가 실행될 때 추가 기록한다. 화면에는 로그를 표시하지 않는다.

중요한 구분:

- `contact_submitted`: 팔 접촉으로 피해 처리를 요청했다는 기록이다. 실제 HP 감소와 같지 않다. 가드나 지연 피해 처리가 있을 수 있다.
- `player_damage`: 기존 HP 적용 함수에서 HP를 설정한 직후다. 실제 감소량은 전후 HP를 비교한다.
- `dodge_accepted`: 회피가 허용되어 회피 이력에 들어간 순간이다. 기존 처리 순서상 스태미나 지불 직전이다.
- `stamina_refund`: 기존 반환 경로에서 스태미나를 돌려준 직후다.
- `decision_distance`: 마지막 판단에서 사용한 거리다. 실시간 거리는 같은 시점의 보스·플레이어 위치로 따로 계산한다.

모든 접촉을 빠짐없이 영상 프레임 단위로 재구성하는 기능은 아니다. 예를 들어 무적 때문에 피해 전달 전 걸러진 접촉은 `contact_submitted`로 기록되지 않는다. 짧은 무적 구간은 0.2초 표본만으로 정확한 시작·끝을 확정할 수 없다.

## 파일과 조절

원본은 `Saved/Logs/Battle.log`의 `[BATTLE_QA]` 행이다. 최신 기록을 요약하려면 프로젝트 폴더에서 다음 명령을 실행한다. 이 작업은 Codex가 대신 할 수 있다.

```powershell
python Tools/ReadCombatQA.py
```

요약 결과:

- `Saved/QA/combat-qa-latest.md`: 읽기 쉬운 선택 횟수·상태 시간·피해·회피·이벤트 시간표
- `Saved/QA/combat-qa-latest.json`: 원본 행과 집계
- `Saved/QA/combat-qa-latest.csv`: 표 형태의 기록

최신 로그 파일의 마지막 기록 세션을 기본으로 읽는다. 이전 세션은 `--session 1`, 특정 로그는 `--log 경로`로 지정할 수 있다. 기록이 없으면 없다고 표시하며, 실제 플레이가 있었다고 추정하지 않는다.

보스 인스턴스의 `bCombatQAEnabled`로 기록을 끄고 켤 수 있다. `CombatQAInterval`은 기본 0.2초이며 사용 범위는 0.1~1초다. 이 기능은 에디터 플레이·개발 환경용이다. 패키징된 Shipping 빌드에서는 PrintString 기록이 보장되지 않는다.

## 이번 작업 확인 범위

블루프린트 연결과 기본값을 재검사했고, 보스·플레이어 컴파일은 오류·경고 0개다. 로그 요약 도구는 세션 분리, 접촉과 실제 피해의 구분, HP 초기화, 표본 공백을 가짜 입력으로 검증했다. **게임을 실행해 확인하지 않았다.** 최초 실제 QA 로그는 사용자의 플레이 후 확인한다.
