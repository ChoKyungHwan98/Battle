# Crunch 보스 포트폴리오 제출 준비 전수조사

2026-10-04 기준. 제출 형식은 **영상·기획서 중심**이다. 이 문서는 기존 계획의 모든 `TODO`를 현재 결함으로 간주하지 않고, 실제 에디터 에셋·소스·PIE 화면·검증 기록과 대조한다. 에디터 빌드 성공과 개별 접촉 시험 통과는 최종 플레이 경험의 합격을 뜻하지 않는다.

## 현재 판정

**작동하는 프로토타입이며, 지금 상태를 완성된 보스전 포트폴리오라고 제출하기에는 이르다.** 핵심 세 시스템은 존재한다. HFSM은 시작·준비·타격·연계·회복·사망 등 행동 경계를 관리한다. Utility AI는 후보 점수를 가중치로 뽑으며, GOAP는 C++ 플래너에서 회전·접근·좌우 간 보기를 검색한다. 오른쪽 위 설명 HUD도 PIE에서 보였다. 에디터 C++ 빌드는 2026-10-04에 성공했고 Blueprint 주요 그래프는 UpToDate였다.

다만 사용자가 약속한 경험인 **밀착 시 자연스러운 간격 조절, 발이 붙는 회전·정지, 방향별 공정한 회피, 패턴 종료 뒤 실제 2–3타 반격**은 종합 플레이 시험으로 아직 입증되지 않았다. `Crunch 전투 AI v2 설계`도 이 다섯 가지와 장시간 행동 분포를 미완료로 명시한다.

### 2026-10-04 P0 부분 진전

3타 연계는 Recovery 진입 뒤에도 마지막 손 판정이 열려 65 피해가 발생하는 결함을 재현하고 수정했다. 현재 `DA_Attack_Combo`의 `ActiveSeconds=0.95`, `TotalSeconds=8.95`다. 수정 후 같은 늦은 피격 시험은 피해 0이고, 가까이에 재배치한 플레이어의 실제 검 입력 3타가 Recovery 안에 적중했다. [재현·한계 기록](../reference/boss_combo_recovery_fix_20261004.md)을 따른다. **실제 구르기에서 3타까지 연결되는지는 아직 P0 미완료**다.

## 현재 에셋에서 직접 확인한 사실

- 보스 배치 크기는 1.3이다. 라이브 PIE 캡슐은 `Visibility=Ignore`로 초기화된다. 에디터에 저장되지 않은 배치 액터의 응답은 `Block`으로 보였으므로, 다시 컴파일·저장·재실행한 뒤에도 라이브 응답을 확인해야 한다.
- 오른손 기본타 액션은 현재 `AM_Boss_Combo_02_SlowRecover`에 연결된다. 10월 1일 접촉 문서의 `DA_Attack_Right → AM_Boss_GutPunch` 서술은 현재 액션 데이터와 다르다. 제출 문서에는 현재 연결을 써야 한다.
- `BP_Player_Combat.DoAttackHitCheck`에는 방사형 피해와 검 궤적 창 로직이 함께 있다. 보스의 손 판정이 물리 소켓 추적으로 바뀌었다는 사실을 플레이어의 모든 공격 판정까지 일반화하면 안 된다.
- C++ GOAP 플래너의 측면 통로 스윕 반경은 45cm이며 배치 보스 캡슐 반경은 약 136.5cm다. 경로가 열려 보이더라도 실제 몸통이 통과하는지 별도 PIE 확인이 필요하다.
- 현재 브랜치는 원격보다 커밋 1개 앞서 있고, 모션 실험실 맵·아레나 외부 액터에 기존 미커밋 변경이 있다. 제출 코드 링크를 만들기 전에 이 변경의 의도를 확인해 재현 가능한 상태로 정리한다. 이번 감사에서는 건드리지 않았다.

## 작업 순서와 촬영 기준

1. **공정성 기준을 먼저 잰다.** 공격마다 실제 손 접촉 시간, 판정 종료, 보스 회복 종료, 플레이어 2–3타 적중을 한 타임라인에 기록한다. 수치 변경은 그 결과를 보고 한다.
2. **발과 몸을 맞춘다.** 시작 연출, 접근 정지, 8방향 이동, 90/180도 턴, 발·다리 접촉을 영상으로 확인하고 눈에 띄는 연결 오류를 고친다.
3. **GOAP의 빈 행동을 채운다.** 기술별 닿는 자리와 밀착·뒤 공간을 사실로 만들고, `RepositionBack` 한 걸음을 추가한다. 공격 가능한 기술이 있다면 공격을 우선 허용한다.
4. **Utility의 결과를 누적해 본다.** 30회 원거리, 20회 공격 후 판단, 10회 밀착, 좌·우 뒤돌기 각 5회를 기록하고 반복·루프·확정 돌진 여부를 확인한다.
5. **영상과 기획서를 같은 사례로 묶는다.** 시작/접근, 방향 전환, 기본타와 휩쓸기·가드 브레이크, 슈퍼맨 펀치, 회피→반격, GOAP 간격 조절을 보여준다. 각 장면에 ‘플레이어 상황 → AI가 읽은 사실 → 선택 이유 → 결과’를 한 줄로 붙인다. DS3 데이터는 참고 출처와 Battle의 독자 설계를 분리한다.

이 포트폴리오를 한 문장으로 설명하면: **“Utility는 지금 어떤 공격·위치 행동이 어울리는지 고르고, GOAP는 주먹이 닿는 자리에 이르는 발걸음을 찾으며, HFSM은 시작한 공격과 플레이어의 반격 시간을 지킵니다.”** 이 문장이 실제 영상에서 확인될 때 제출 준비가 끝난다.
