# Crunch의 선택지: Utility AI·GOAP·사용하지 않는 모션

2026-10-05. 영상·기획서 제출을 위한 **현재 상태와 다음 설계 결정**이다. 액션 데이터는 Unreal Editor MCP에서 직접 읽고, GOAP 행동은 `BossPositionPlanner.h/.cpp`와 대조했다. 아래 가중치는 실제 사용 확률이 아니다.

## 먼저 구분할 것

- **공격 모션**은 보스가 실제로 보여주는 동작이다. `Combo_01`과 `Combo_02`는 각각 한 번 휘두르는 단타다. 이름의 `Combo` 때문에 한 에셋을 여러 타격으로 세지 않는다.
- **Utility AI의 카드**는 지금 가능한 공격이나 위치 잡기 의도를 점수로 비교해 하나를 뽑는다.
- **GOAP의 행동**은 공격 모션이 아니라, 주먹이 닿는 자리를 만들기 위한 `돌기·접근·옆걸음` 같은 단계다.
- **HFSM**은 선택된 행동이 준비·타격·연계·후딜을 지키게 한다.

DS3 군다 원본에서 참고한 것은 거리·방향에 따라 **복수 행동의 가중치가 바뀌고**, 공격 후 별도 움직임이 있다는 점이다. Battle의 Utility·GOAP·HFSM 구성은 우리 설계다. [원본 추출 기록](../research/ds3_gundyr_original_ai_extract.md)의 수치를 Crunch 확률로 옮기지 않는다.

## 현재 Utility 카드

| 카드 | 현재 전투 연결 | 자동 선택 상황·제약 |
| --- | --- | --- |
| 왼손 휘두르기 | `Combo_01_Slow`를 다듬은 준비 동작 + Recovery | 기본 가중치 35, 0–285cm |
| 오른손/바디 펀치 | `Combo_02_Slow` 준비 동작 + Recovery | 35, 0–200cm |
| 3타 연계 | `Combo_01 → Combo_02 → Ability_Hook` 계열 몽타주 | 40, 0–285cm, 최근 회피 관찰, 8초 재사용 간격 |
| 양손 휩쓸기 | `Ability_Hook_Empowered` | 22, 170–285cm, 최근 회피 시 선호 증가, 4초 재사용 간격 |
| 가드 브레이크 | `Ability_GutPunch` | 40, 170–285cm, 가드 압력·최근 가드 관찰, 6초 재사용 간격 |
| 슈퍼맨 펀치 | `DashingCross_Start` 보정본 → `DashingCross` → 결과별 Recovery | 12, 400–900cm, 12초 재사용 간격. 첫 관찰 직후 즉시 돌진 제한 |
| 점프 내려찍기 | 별도 `Jump_*` 몽타주 | 2페이즈 첫 사용은 별도 약속. 이후 먼 거리 후보. 1페이즈 일반 추첨에서 제외 |
| `Combo_03` 단타 | `Ability_Combo_03` | 데이터는 있지만 `bEnabled=false`. 손은 닿아도 화면상 너무 높은 타격을 해결하기 전까지 자동 선택하지 않음 |
| 접근 | 공격 몽타주 없음 | 원거리 기본 의도 가중치 88. GOAP의 `DirectApproach`가 실제 위치 단계를 찾음 |

총 **9개 데이터 카드 = 공격 8개 + 접근 1개**다. 자동 공격은 `Combo_03`을 빼면 7개, 점프를 아직 사용하지 않는 1페이즈에는 6개다. 이 숫자는 전투가 다양하게 *느껴진다*는 증거가 아니다. 같은 거리에서 허용되는 카드가 적거나 후딜 뒤 매번 같은 위치를 잡으면 여러 에셋이 있어도 반복처럼 보인다.

### 사용하지 않거나 아직 선택하지 않은 모션

- `Ability_Uppercut`은 **현재 자동 공격 데이터나 3타 연계의 마지막 구간에 연결되지 않았다.** 사용자가 처음 지정한 `01 → 02 → Ability_Uppercut`과 현재 `01 → 02 → Ability_Hook`이 다르다. `Ability_Combo_03` 단타를 끈 이유를 `Ability_Uppercut`에도 그대로 적용하면 안 된다. 두 모션의 타격 높이와 연결 자세를 따로 비교해야 한다.
- `Ability_Combo_04`는 현재 자동 공격 몽타주에 없다. `Combo_02`와 역할이 겹치는지 시각 비교 후 결정한다. 이름이 하나 더 있다는 이유만으로 카드를 늘리지 않는다.
- `Fast` 계열은 이 느린 복서의 기본 박자를 무너뜨릴 수 있으므로 새로운 패턴으로 자동 등록하지 않는다. 필요하다면 2페이즈의 **명확한 변화**로 먼저 화면 시험한다.
- `Additive`는 독립 공격으로 세지 않는다. 기본 동작에 더하는 자세 변화다. `Slow`와 `Recovery` 계열은 이미 일부 실제 몽타주에 사용 중이다.

## 현재 GOAP가 할 수 있는 일과 빠진 일

코드의 목표는 `PrepareStrike`, `PrepareGuardBreak`, `ProbeThenStrike` 세 가지이고, 위치 행동은 `DirectApproach`, `FaceTarget`, `OrbitLeft`, `OrbitRight` 네 가지다. 현재 사실은 근접 거리, 정면, 간보기 완료, 가드 브레이크 거리 네 비트다. 플래너는 가능한 단계의 전제·결과·비용을 검색하므로 고정된 순서표는 아니다.

다만 **거리 안에 있다 = 손이 닿는다**는 아직 성립하지 않는다. 너무 붙어서 주먹이 플레이어 몸 안쪽을 지나는 경우를 나타내는 기술별 `InAttackBand`와 `TooCloseForAll`, 뒤 공간 검사, `RepositionBack`이 없다. 현재 옆길 검사도 반경 45cm 구형 스윕인데 배치 보스 캡슐 반경은 약 136.5cm다. 실제 몸이 못 지나갈 옆길을 가능하다고 볼 수 있어 경로·발 접지를 시험해야 한다. [v2 설계](crunch_combat_ai_v2_design.md)의 뒤걸음은 **닿는 공격이 하나도 없을 때만** 허용한다.

## 패턴을 늘리는 순서

1. **현재 6개가 실제로 등장하는지 기록한다.** 원거리 독립 판단 30회, 공격 후 판단 20회, 밀착 10회를 모아 각 카드의 후보 진입·점수·제외 이유·실제 선택을 센다. 휩쓸기가 안 보이면 `가중치가 낮아서`인지 `170cm 최소 거리·쿨다운 때문에 후보 밖인지`부터 구분한다.
2. **닿는 자리와 보이는 판정을 맞춘다.** 170/230cm와 캡슐 접촉에서 각 손의 실제 접촉을 확인한다. 공격 후보에서 제외되는 이유를 고친 뒤 점수를 조절한다. 주먹을 억지로 크게 만들어 다양성을 만들지 않는다.
3. **위치 패턴을 완성한다.** 접근→감속→정지, 뒤를 잡혔을 때 턴, 공격 후 가끔 옆걸음, 모두 안 닿는 밀착에서 한 번 뒤걸음을 연결한다. GOAP 단계 종료 후 실제 거리·각도를 다시 확인한다.
4. **사용자가 원한 3타를 다시 비교한다.** `01 → 02 → Ability_Uppercut`을 기존 훅 버전과 같은 카메라·거리에서 비교한다. 연결 자세, 세 번째 손 접촉, 점프 후 후딜과 플레이어 반격을 모두 통과하면 교체한다. 필요하면 `Ability_Uppercut` 단타는 별도 카드로 만들되, 3타 마지막과 동시에 남발하지 않도록 공유 반복 감점을 둔다.
5. **그 뒤에만 신규 카드를 검토한다.** `Combo_04`가 오른손과 구별되는 텔레그래프·회피 방향·후딜 보상을 제공하면 사용한다. 같은 역할이면 추가하지 않는다. 2페이즈의 점프도 A/B/C 회피 결과가 실제 조작으로 입증된 뒤 패턴 다양성으로 내세운다.

포트폴리오에서는 기술 개수보다 **같은 상황에서도 접근·공격·옆걸음 중 무엇을 골랐는지, 왜 후보가 바뀌었는지, 플레이어가 읽고 대응할 수 있었는지**를 한 장면으로 보여주는 편이 강하다. `88:12`나 `35:22`는 출현 확률이라고 말하지 않는다. HUD에 후보 점수뿐 아니라 *제외 이유*와 GOAP의 현재 목표·실패 이유가 보여야 선택을 설명할 수 있다.
