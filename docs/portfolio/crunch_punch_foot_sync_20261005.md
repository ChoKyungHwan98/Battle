# 공격의 디딤발과 전진을 맞춘 이유

## 원했던 경험

Crunch는 굼뜨지만 몸을 실어 때리는 기계 복서다. 플레이어가 조금 물러나도 발을 앞으로 내딛으며 주먹이 따라와야 한다. 플레이어는 그 몸과 팔의 움직임을 보고 피할 순간을 판단한다.

사용자가 뜻한 것은 **공격 모션 안에서 발을 내밀고 몸을 실어 때리는 것**이었다. 따로 걷고 도착한 다음 주먹을 내는 것으로는 원하는 감각을 만들기 어려웠다.

## 만들고 확인하면서 발견한 문제

처음에는 가까우면 공격하고, 멀면 접근했다. 사용자는 ‘계속 쫓아오기만 한다’고 지적했다. 그래서 공격 앞에 한 발·두 발 걷기를 붙였고, 뒤로 걷는 플레이어에게 닿도록 이동량도 늘렸다. 하지만 사용자는 걸음이 너무 빠르다고 느꼈다. 속도를 복원해도 핵심 문제는 남았다. 걷기와 공격을 이어 붙이는 방식 자체가 사용자가 말한 디딤 공격과 달랐다.

이번에 기본 왼손·오른손 공격의 발과 골반 위치를 모션 시간별로 읽었다. 두 공격 모두 발을 들어 앞으로 뻗고 내려놓는 동작이 있었지만, 캐릭터 전체의 기준 위치는 움직이지 않았다. 기존의 별도 이동은 그 발동작과 다른 속도 곡선을 사용하고 있었다.

## 이번에 바꾼 행동

1. 기본 왼손·오른손을 선택하면 그 주먹 모션으로 바로 들어간다. 공격 앞에 따로 붙였던 걷기 형태는 선택하지 않는다.
2. 모션에서 발이 앞으로 움직이는 흐름을 읽어 전진 진행표를 만들었다. 발을 준비할 때는 조금 움직이고, 발을 뻗는 구간에서 나머지 전진이 일어난다.
3. 진행표는 실제 재생 중인 공격 모션의 시각으로 읽는다. 재생 속도가 바뀌어도 같은 자세에서 같은 비율만큼 전진한다.
4. 발이 내려오는 뒤쪽 구간에서는 전진을 끝낸다. 공격이 끝날 때까지 계속 추격하지 않는다.
5. 가까이 붙어 있으면 전진량을 줄인다. 몸 앞에 여유가 없거나 월드 충돌이 생기면 더 들어가지 않는다.

포트폴리오에서 설명할 문장:

> **“플레이어가 조금 물러났을 때도 보스가 발을 내딛으며 몸을 실어 공격하도록 만들었습니다. 처음에는 공격 앞에 걷기를 붙였지만 동작이 분리되어 보였습니다. 그래서 공격 자체의 발동작에 전진 타이밍을 맞추고, 가까운 거리에서는 이동량을 줄이도록 수정했습니다.”**

## 첫 적용값

| 항목 | 왼손 | 오른손 |
|---|---:|---:|
| 모션 안에서 이동을 허용한 구간 | 약 0.033~0.400초 | 약 0.033~0.400초 |
| 전체 재생 속도 | 0.75배 | 0.75배 |
| 실제 재생 시간으로 환산한 이동 구간 길이 | 약 0.489초 | 약 0.489초 |
| 요청 전진량 상한 | 약 66cm | 약 87cm |
| 공격 선택 거리 상한 (캐릭터 중심 간 거리) | 350cm | 350cm |

이동 구간 시각은 몽타주 안의 시간이다. 공격 시작 전 별도 준비 시간 0.25초는 표에 포함하지 않았다. 진행표는 모션 약 0.367초에서 전진을 모두 끝내고 0.400초까지 그 위치를 유지한다.

전진량은 현재 배치된 보스 크기 1.3배에서, 공중에 든 발의 앞쪽 이동 폭을 기준으로 잡은 **첫 조정값**이다. 원본 모션에 기록된 전체 몸 이동량이나 DS3의 수치는 아니다. 모션 내부의 발 이동에 캐릭터 위치 이동을 더하는 보정이며, 발을 바닥에 정확히 고정하는 별도 보정은 아직 없다. 따라서 실제 화면의 발 미끄러짐은 반드시 확인해야 한다.

350cm는 후보로 선택할 수 있는 거리다. 그 거리의 모든 위치·자세에서 반드시 맞는다는 의미는 아니다. 접근 행동이 공격 선택으로 넘어가는 거리도 350cm로 맞췄다. 먼 거리에서 일반 접근하는 행동은 계속 필요하다.

## HFSM / Utility / GOAP의 역할

- **Utility:** 어떤 공격을 쓸지 고른다. 이번에는 후보 점수·반복 감점·추첨 규칙을 바꾸지 않았다. 기본 펀치의 선택 거리와 실행 형태를 조정했다.
- **HFSM:** 선택한 공격을 준비·타격·후딜 순서로 진행한다. 이번 전진은 그 공격 안에서 정해진 구간에 실행된다.
- **GOAP:** 공격할 위치를 잡는 흐름을 맡는다. 이번 수정은 위치 탐색 방식의 변경이 아니라, 위치를 잡은 뒤 실행하는 주먹의 움직임을 바꾼 것이다.

## 확인한 사실과 다음 플레이 확인

블루프린트 컴파일 오류·경고는 0건이다. 진행표가 뒤로 되돌아가지 않고 0에서 1까지 증가하는지, 모션의 이동 구간과 연결되었는지, 이전 걷기 형태로 들어가는 실행 경로가 끊겼는지 확인했다. 원본 자세, 주먹 판정 구간, 불꽃 시각과 피해량은 이번에 수정하지 않았다. 기본 공격 카드를 사용하는 Arena와 MotionLab이 같은 수정된 보스 실행 함수를 사용한다.

사용자 요청에 따라 게임 실행과 화면 캡처는 하지 않았다. 자연스러움과 실제 명중은 검증 대기다. MotionLab 기본 왼손·오른손에서 아래 순서로 확인한다.

1. 조금 떨어져 있을 때 발을 내미는 순간 몸도 전진하는가?
2. 착지한 뒤에도 몸이 계속 미끄러지지는 않는가? 특히 뒤쪽 지지발을 확인한다.
3. 바짝 붙었을 때 몸이 과하게 밀고 들어가거나 주먹이 지나치지는 않는가?
4. 뒤로 조금 걸을 때 위협이 유지되는가? 충분히 거리를 벌리면 피할 수 있어야 한다.

QA의 `punch_foot_sync`는 이번 이동 방식이 켜졌는지, `foot_alpha`는 마지막으로 읽은 전진 진행 비율이다. `step_distance`는 할당한 이동량이고 `step_progress`는 계산상 진행량이므로, 실제 이동 거리·명중 여부는 위치 변화와 피해 기록을 함께 본다. 기존 `advance_steps=0`은 별도 준비 걷기를 붙이지 않았다는 뜻이다.
