# Crunch 전용 모션 직접 제작 계획

## 사용자가 정한 조건

- Mixamo 사용 금지.
- 외부 모캡 사용 금지.
- 다른 캐릭터의 애니메이션을 Crunch에 옮겨 사용하지 않음.
- Crunch 원본 모션을 편집하거나 Crunch 스켈레톤에 직접 새 동작을 제작함.
- 참고 영상은 자세·리듬 분석용으로 볼 수 있지만 영상에서 모캡 데이터를 추출하는 제작 경로는 사용하지 않음.
- 외부 모션 라이브러리 구매·리타깃은 이 문제의 해결안에서 제외함.

## 만들려는 경험

왼발이 앞에 있는 Crunch가 오른발을 앞으로 내딛고, 그 발로 몸을 받치며 왼손을 휘두른다.
느리고 무거운 복서처럼 몸의 무게가 공격에 이어져야 한다. 몸만 앞으로 미는 연출이나 달리기 자세의 단순 합성은 완료로 인정하지 않는다.
제자리 왼손의 사용자 측정값 345cm는 유지하며, 전진형은 시작 거리 550cm 도달을 목표로 한다.
몸 전진량 205cm는 이전 제작값이다. 새 동작에서도 그대로 쓰면 목표를 달성한다는 공식으로 취급하지 않는다.

## 에셋이 없을 때의 제작 방법

### 1. Crunch를 직접 조절할 손잡이 만들기

Control Rig는 몸·발·손을 원하는 위치로 조절하는 편집용 손잡이다.
저장된 프로젝트 목록에는 마네킹용 리그가 있고 Crunch 전용 ControlRigBlueprint는 발견되지 않았다.
기존 원본을 확인하고 Crunch에 맞는 편집용 리그를 구성·검증한다.

먼저 몸 전체 이동, 골반, 양발, 무릎 방향, 상체, 양손을 제어한다.
단순히 뼈 이름을 연결한 것으로 완료하지 않는다. 발을 고정하고 몸을 옮겼을 때 다리가 꺾이지 않는지,
손을 움직일 때 기계 부품·추가 뼈가 따라오는지, 원본 자세를 편집 키로 옮겼을 때 유지되는지 확인한다.
원본 수정 레이어를 사용하려면 Backwards Solve가 실제로 작동해야 한다.

### 2. 중요한 자세를 직접 만들기

처음부터 전체 프레임을 촘촘히 만드는 대신 다음 자세를 먼저 만든다.

| 자세 | 화면에서 보여야 할 것 |
|---|---|
| 준비 | 왼발이 앞에 있으며 공격을 읽을 수 있는 준비 자세 |
| 오른발 전진 | 몸을 받치는 왼발과 앞으로 옮겨지는 오른발이 구분됨 |
| 오른발 착지·체중 이동 | 오른발을 짚으면서 골반·몸통이 앞으로 따라옴 |
| 왼손 타격 | 발·골반·상체·주먹이 하나의 공격으로 이어짐 |
| 회복 | 공격에 실었던 몸을 거두고 다음 행동이 가능한 자세로 돌아옴 |

Crunch 원본 왼손의 읽히는 휘두르기 궤적은 출발점으로 사용한다.
발과 몸의 전진은 해당 공격을 위해 직접 제작한다. 달리기 하체를 그대로 붙이는 것을 기본 방식으로 삼지 않는다.

### 3. 자세 사이 연결 만들기

준비에서 발을 드는 속도, 착지 때의 감속, 골반·상체 회전, 공격 후 몸을 거두는 시간을 조절한다.
바닥을 받치는 발은 접촉 구간에 맞게 유지하고, 발을 들어 옮기는 구간은 고정하지 않는다.
공격 시작과 끝 자세를 기존 대기 자세에 맞춰 연결한다.
모션의 몸 이동과 게임의 별도 이동이 중복되어 미끄러지지 않는지 확인한다.

### 4. 모션 품질과 게임 기능을 따로 검사하기

모션: 바닥이 보이는 정면·측면에서 정상 속도로 무게감·동작 순서·회복을 확인한다.
느린 재생은 발 미끄러짐, 무릎 급회전, 상체 튐을 찾는 보조 검사다.
관절 회전 수치가 작아졌다는 이유만으로 자연스러움이 확인됐다고 보고하지 않는다.

게임: Root Motion이 실제 캐릭터를 이동시키는지, 550cm에서 손 판정이 실제로 닿는지,
한 번의 공격이 한 번만 피해를 주는지, 벽에 막히는지, 정해진 시점 이후 방향이 잠기는지 확인한다.
범위를 맞추기 위해 보이지 않는 공격 판정을 과하게 키우지 않는다.

## 남은 불확실성과 완료 기준

Crunch 전용 리그의 생성·베이크·원본 자세 재현은 아직 검증되지 않았다.
리그가 있어도 동작의 예술적 품질이 자동으로 보장되는 것은 아니다. 키 자세와 연결을 반복해서 보정해야 한다.
이번 작업의 우선 시험은 전진형 왼손 한 개다. 해당 모션의 품질을 사용자가 받아들이고 실제 접촉 검사가 통과한 뒤,
다른 공격 제작과 Utility/GOAP 연결에 같은 절차를 적용한다.

기획자는 원하는 동작·리듬과 결과 품질을 판단하고, Codex는 리그·키프레임 편집·저장·검사를 담당한다.
구현 방식에 대한 도움을 요청하는 이번 대화에서는 에셋을 변경하지 않았으며, 이 문서는 제작 계획과 조건 기록이다.
