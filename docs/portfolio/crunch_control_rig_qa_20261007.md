# Crunch 전진형 왼손: Control Rig 제작 및 QA

## 이번에 만드는 경험

왼발이 앞인 준비 자세에서 오른발을 앞으로 옮기고, 바닥을 짚으며 몸을 실어 왼손을 휘두른다.
기존 왼손의 공격 느낌을 출발점으로 삼는다. 전진형의 시작 거리 550cm 접촉은 목표이며,
몸의 이동량 205cm를 입력했다는 이유만으로 도달이나 모션 품질을 합격으로 판단하지 않는다.

## 제작 경로

현재 Unreal MCP → UE5.8 Control Rig / Sequencer → AnimSequence Bake → Montage / Notify → MotionLab.
Mixamo, 외부 모캡, 다른 캐릭터의 모션은 사용하지 않는다. 달리기 하체를 붙이는 방식도 사용하지 않는다.
원본 Crunch 시퀀스와 제자리 공격은 보존한다.

| 자산 | 역할 |
|---|---|
| `/Game/BossArena/Boss/Authoring/CR_Crunch_Attack` | 원본 자세용 FK, 발 목표, 무릎 방향, 다리 IK, Backwards Solve |
| `/Game/BossArena/Boss/Authoring/LS_Crunch_RightStep_LeftSwing` | 수정 가능한 공격 편집 원본 |
| `/Game/BossArena/Boss/Authoring/AS_Crunch_RightStep_LeftSwing` | Sequence에서 출력한 게임용 애니메이션 |
| `/Game/BossArena/Boss/Authoring/AM_Crunch_RightStep_LeftSwing` | 타격/FX Notify를 배치하는 Montage |

## 사용자가 확인할 것

### 2026-10-07 원본 샘플 조사와 전신 재생 보정

사용자가 지목한 세 자산을 Unreal MCP로 직접 확인했다.

| 자산 | 실제 연결과 역할 |
|---|---|
| `AnimationTestMap` | 원본 `CrunchPlayerCharacter`가 배치돼 있고 Player 0이 조종한다. 현재 디딤 실험을 실행하는 MotionLab과 별개다. |
| `CrunchPlayerCharacter` | 원본 `Crunch_AnimBlueprint`를 사용한다. 클릭 공격은 원본 `Ability_Combo_01/02/03_Montage`를 1배속으로 재생한다. |
| `Crunch_AnimBlueprint` | 이동 시작·달리기·정지, 상체 공격과 하체 이동의 혼합, 전신 공격, 마지막 다리 IK를 연결한다. |

보스 `ABP_Boss_Crunch`는 상체/전신 혼합과 다리 IK를 계승했지만,
이동 시작·정지 상태 머신의 출력 대신 `BS_Boss_8Way`를 `Ground_Loco`에 직접 연결한다.
따라서 원본의 이동 시작·정지 모션이 현재 보스에서도 실행된다고 해석하면 안 된다.

디딤 공격의 재생 문제도 확인했다. 보스는 이동 속도로 `IsAccelerating`을 판단하므로,
Root Motion으로 전진하는 공격도 이동 중으로 분류했다. 공격의 `FullBody` 값이 0이면
그때 하체를 이동 모션으로 섞는다. 원본 왼손 모션의 `FullBody` 커브도 실제 값은 0이었고,
새 디딤 출력에는 해당 커브가 없었다. 단순한 커브 유무보다 실제 재생 값을 검사해야 한다.

수정은 `AS_Crunch_RightStep_SingleBeat`에만 적용했다. 출력 전체에 `FullBody=1`을 기록해
오른발 디딤과 기존 왼손 공격을 전신으로 유지한다. 다시 Bake해도 같은 표시를 넣도록
`AuthorCrunchSingleBeat.mark_full_body()`를 추가했다. 원본 샘플 세 자산과 보스 AnimBP는 수정하지 않았다.

동일한 샘플 캐릭터(크기 1)에서 원본 AnimBP와 보스 AnimBP로 같은 디딤 몽타주를 비교했다.
애니메이션 약 0.40초의 왼발 위치 차이는 보정 전 약 107.68cm, 보정 후 약 0.37cm였다.
이는 가까운 재생 시점을 비교한 혼합 문제의 진단값이며, 발 접지나 모션 품질의 합격 기준이 아니다.

MotionLab 시나리오 `20261007T114700Z-1AAFF840`는 실제 몽타주 실행,
타격 창 시작 약 0.554초, 이동 중 전신 유지 105개 관측 프레임,
이동 중 잘못된 하체 혼합 0개 관측 프레임을 확인했고 정상 종료했다.
사용자 화면 최소화 때문에 게임 화면 캡처는 실패했다. **모션의 자연스러움은 아직 사용자 QA 대상이다.**

이번 보정 후에도 오른발 착지, 골반의 체중 이동, 회복 자세 연결을 구분해 확인해야 한다.
애니메이션 키가 올바르게 출력됐다는 검사만으로 게임 속 최종 동작도 같다고 판단하지 않는다.

### 2026-10-07 원본 하체 반전 v6 — 현재 모션랩 연결본

사용자가 제안한 **“기존 첫 동작의 허리 아래를 반대편에 붙이기”**를 구현했다.
바탕은 v5와 같은 승인된 제자리 공격이다. 원본 자체에 들어 있는 왼발의 들기·착지를
오른발에 옮겼으며, 임의로 만든 발 들기 곡선이나 추가 준비 시간을 사용하지 않는다.

| 기획 의도 | 이번 처리 |
|---|---|
| 기존 왼발 앞 자세로 시작 | 첫 자세는 기존 그대로 유지한다. 오른발이 움직이면서 반전된 동작으로 연결한다. |
| 오른발 한 번 + 기존 왼손 공격 | 원본 다리·골반·기계 관절을 함께 좌우 반전한다. 허리에서 보정해 기존 상체 공격의 방향과 시간은 유지한다. |
| 왼발은 지지하고 추가 걸음을 넣지 않음 | 왼발을 공격 동안 같은 위치에 둔다. 원래 회복으로 연결할 때 고정을 풀며, 별도의 전진 걸음은 만들지 않는다. |

발만 반전하면 골반과 무릎의 방향이 맞지 않으므로 하체를 함께 반전하고,
지지 발과 무릎 방향을 Control Rig에서 보정했다. 기존 몸 전진 곡선과 재생 속도 0.75,
물리 타격·FX Notify 시간은 유지했다. 이번 작업은 사거리 튜닝이 아니다.

모션랩 플레이 → **L 세 번 → 1키**. 실행 이름은 **`원본 하체 반전 + 왼손 · v6`**다.
기본 제자리 모드의 1과 비교한다. 거리 때문에 요청이 거부되면 J 사거리 측정을 켠다.
확인할 것은 **오른발과 왼손이 같은 한 박자에 나오는지, 착지에서 무릎이 튀지 않는지,
공격 뒤 회복 연결이 자연스러운지**다.

| 자산 | 역할 |
|---|---|
| `CR_Crunch_MirroredLower` | 별도 수정용 리그 |
| `AS_Crunch_MirroredLower_Base` | 원본 하체를 반전하고 상체 동작을 유지한 바탕 |
| `LS_Crunch_MirroredLower_LeftSwing` | 발 고정과 무릎 방향을 조정하는 편집 Sequence |
| `AS_Crunch_MirroredLower_LeftSwing` | 게임용 출력 |
| `AM_Crunch_MirroredLower_LeftSwing` | 기존 타격·FX 시간 유지, 수동 전진 Notify 제거 |

위 자산은 `/Game/BossArena/Boss/Authoring/`에 있다. 원본과 이전 v5는 보존했다.
현재 연결은 모션랩 비교용 행동 `DA_Lab_Left_RightFootPlant`다. Arena로 확대하지 않았다.

제작 프레임에서 발 목표 오차는 약 0.010cm 미만, 기존 상체 회전과의 차이는 약 0.005도 미만이었다.
원본 첫/끝 자세와 주요 관절의 위치 차이도 약 0.005cm 미만이었다.
복제 리그의 그래프 연결 캐시가 빠지는 문제는 저장 후 해당 패키지를 다시 불러오는 방식으로 해결했다.
최종 리그는 Forward Solve 328개, Backwards Solve 318개의 중복 없는 연결을 확인했다.

실제 게임 시나리오 `20261007T121939Z-60ACBDE9`는 9개 검사를 통과하고 PIE를 정상 종료했다.
새 몽타주 실행, 타격 창 시작 약 0.564초, 이동 중 전신 유지 98개 관측 프레임,
잘못된 이동 모션 덮어쓰기 0개 관측 프레임을 확인했다.
공격 중 오른발 높이 변화는 약 25.2cm, 지지하는 왼발 위치 변화는 약 4.50cm였다.
이는 바닥 접지의 최종 합격 판정이 아니며, 혼합 시작과 실제 게임 재생을 포함한 관측값이다.
몸은 최대 약 71.5cm 전진했다. 이번 시험에서 400cm 정지 대상에게 피해가 발생했으나,
550cm 사거리나 움직이는 플레이어 대응을 검증한 것은 아니다.

**모션의 자연스러움은 사용자 QA 대상이다.** 화면 캡처와 수치 검사를 품질 승인으로 대신하지 않는다.
제작: `Tools/AuthorCrunchMirroredLower.py`의 `prepare → key_step → bake_validate → integrate`.
실제 게임 연결 검사: `Tools/TestCrunchMirroredLower.py`.

### 2026-10-07 원래 템포의 오른발 디딤 v5 — 이전 모션랩 연결본

최신 사용자 설명을 기준으로 목표를 정정했다.
**왼발이 앞인 기존 자세 → 오른발을 앞으로 내딛으며 기존 왼손 공격을 한 박자에 실행**한다.
v4의 `오른발 → 추가 왼발 + 펀치`는 이 목표와 달랐다.

이번 바탕은 사용자가 좋아한 제자리 공격 `AM_Boss_Combo_01_LowRecover`의 실제 구성이다.
수정하지 않은 기본 `Ability_Combo_01`을 다시 느리게 배치한 v3/v4 바탕은 사용하지 않는다.
기존 준비, 팔 동작, 회복의 시간 배치를 그대로 복제했다. 추가 준비 시간을 넣지 않았다.
기존 공격의 0.75 재생 속도와 FX·물리 타격 Notify 시간을 유지한다.

| 구간 | 원하는 모습과 변경 |
|---|---|
| 준비 | 기존 왼발 앞 자세와 공격 준비를 유지한다. |
| 공격 | 원래 주먹이 나가는 시간 안에 오른발을 내딛고 몸을 싣는다. 별도의 왼발 걸음을 넣지 않는다. |
| 회복 | 같은 오른발을 회수하며 기존 회복 자세로 연결한다. 추가 전진 걸음을 넣지 않는다. |

왼발의 기존 발 위치·발목 동작은 보존한다. 원래 모션에 있는 뒤꿈치 움직임까지 제거한 것은 아니다.
오른발 착지는 애니메이션 시간 0.40초로, 기존 손 판정 구간 0.346667–0.486667초 안에 배치했다.
착지·체중 이동을 위한 골반 높이 보정은 최대 애니메이션 공간 6cm다.
회복에서는 오른발과 몸을 회수한다. 총 전진량이나 목표 사거리를 맞추는 작업은 하지 않았다.

기존 준비 모션의 Root 회전은 약 -12.8도에서 0도로 바뀐다.
그 상태로 이동을 추출하면 몸 회전이 달라 보일 수 있어, Root를 회전 없는 기준으로 정리하고
기존 회전을 Root 직계 자식에 옮겼다. 이 변환 전후 주요 관절의 보이는 위치 차이는
확인 시점에서 약 0.0003cm 미만이었다. 캐릭터 캡슐의 회전으로 공격을 추적하게 만든 처리가 아니다.

**확인 방법: MotionLab 플레이 → L 세 번 → 1키.**
실행 이름은 `오른발 디딤 + 왼손 · 원래 템포 v5`, 몽타주는 `AM_Crunch_RightStep_SingleBeat`다.
기본 제자리 모드의 1과 비교해, 오른발과 왼손이 한 박자에 나가는지 확인한다.
J 사거리 측정을 켜면 거리 요청 제한과 별개로 동작을 비교할 수 있다.

| 자산 | 역할 |
|---|---|
| `/Game/BossArena/Boss/Authoring/AS_Crunch_ApprovedPunch_Base` | 승인된 제자리 공격·회복의 시간과 보이는 자세를 보존한 편집 바탕 |
| `/Game/BossArena/Boss/Authoring/LS_Crunch_RightStep_SingleBeat` | 오른발 디딤과 체중 이동을 편집하는 Sequence |
| `/Game/BossArena/Boss/Authoring/AS_Crunch_RightStep_SingleBeat` | 게임용 출력 |
| `/Game/BossArena/Boss/Authoring/AM_Crunch_RightStep_SingleBeat` | 기존 몽타주의 별도 복제본. FX·타격 시간 보존 |

왼발의 기존 발 위치 차이는 제작 프레임에서 약 0.007cm 미만,
오른발 목표 오차는 약 0.013cm 미만이었다. 이 수치는 편집 내용의 출력 검사다.
동작이 자연스럽다는 최종 판정은 사용자 QA 대상이며 Arena에는 아직 확대하지 않았다.

실제 PIE에서 새 몽타주 재생과 원래 템포의 타격 창을 확인한다.
이전 v4 영상의 판정 시작은 약 0.90초, 제자리 공격은 약 0.55초였다.
v5 초기 기술 검사에서는 약 0.569초였다. 최종 Root 정리 후 실제 PIE에서는 약 **0.545초**였다.
최종 시나리오 `20261007T110656Z-C105D58F`는 새 몽타주 재생과 타격 창 시점 검사를 통과했고
검사 종료 후 PIE도 정상 종료됐다. 이 시나리오는 최종 저장된 애니메이션·몽타주·행동 정의를 대상으로 했다.
거리·피해량 합격을 판정한 검사가 아니다.

구현: `Tools/AuthorCrunchSingleBeat.py`의 `prepare → key_step → bake_validate → integrate`.

### 2026-10-07 왼발 + 왼손 연결 v4 — 이전 연결본

사용자 수정 지시: 지금 먼저 움직이는 오른발을 유지한다.
그다음 왼발을 내딛으면서 기존 왼손 공격이 이어지게 한다.
이번 작업은 애니메이션 연결에 한정하며 사거리·피해량·공격 판정 수치를 조정하지 않는다.

이전 버전은 오른발을 디디고 왼손을 휘두른 다음, 회복 구간에 왼발이 따라왔다.
이번에는 왼발 동작을 왼손 공격 구간으로 앞당겼다.
오른발의 위치·회전 키와 바탕의 골반 회전·팔 동작은 보존했다.
몸이 왼발과 함께 실리도록 기존 체중 이동의 시점도 맞췄다.
새로운 오른발 걸음이나 공격 뒤의 추가 발걸음을 넣지 않았다.

| 순서 | 동작 |
|---|---|
| 1 | 기존 오른발 디딤 |
| 2 | 왼발을 내딛는 동안 기존 왼손 휘두르기 |
| 3 | 디딘 자세를 유지하며 회복·대기 연결 |

**플레이 → L 세 번 → 1키**. 실행 이름은 `오른발 → 왼발 + 왼손 · 모션 연결 v4`.

### 2026-10-07 원본 보존 v3 — 이전 연결본

이번 영상에는 `기본 제자리 · 몸 전진 없음`, `몸 전진 0cm`가 표시돼 있었다.
따라서 그 영상으로 v2 디딤 공격의 품질을 판단하지 않는다.

새 버전은 수정하지 않은 Crunch `Ability_Combo_01`을 복제한 별도 바탕에서 시작한다.
준비와 회복 시간을 조정하고, 시작과 마지막은 `Idle_Combat` 자세로 연결한다.
원본의 골반 회전·척추·팔 동작을 보존하며, 원본 위에 수정용 Control Rig 레이어를 얹는다.
팔 동작을 다시 만들거나 골반 회전을 척추로 옮기는 이전 처리는 사용하지 않는다.

| 구간 | 변경 내용 |
|---|---|
| 준비 | 대기 자세에서 원본 준비 자세로 연결한다. 원본의 골반 이동을 유지하며 몸 이동을 보정한다. |
| 주 디딤 | 오른발을 한 번 앞으로 내딛는다. 왼발은 바닥을 지지한다. |
| 왼손 공격 | 원본 골반 회전과 팔 동작을 유지한다. 지지 다리가 과하게 뻗지 않도록 몸을 잠깐 낮춘다. |
| 회복 | 왼발이 한 번 따라온다. 이후 추가 발걸음 없이 원본 대기 자세로 연결한다. |

몸을 낮추는 최대 보정은 애니메이션 공간 10cm, 배치 크기 1.3에서 약 13cm다.
몸 이동 205cm 전체가 주먹이 닿기 전에 일어나지는 않는다. 일부 이동은 뒷발이 따라오는 회복 구간에 있다.
따라서 총 이동 205cm를 사거리 증가 205cm로 해석하면 안 된다.

확인 방법: **PIE 시작 → L 세 번 → 오른발 디딤 모드 → 1**.
기본 제자리 모드의 1은 기존 모션이다. 실제 실행된 새 몽타주는
`AM_Crunch_LeftSwing_OriginalStep`, 행동 이름은 `오른발 디딤 → 왼손 · 원본 보존 v3`다.
우선 가까운 배치에서 발·골반·주먹이 연결되는지 확인한다.

| 새 자산 | 역할 |
|---|---|
| `/Game/BossArena/Boss/Authoring/AS_Crunch_LeftSwing_OriginalBase` | Crunch 원본을 복제한 바탕. 준비·회복 연결과 시간만 조정 |

수정 레이어에는 Root, 골반의 작은 위치 보정, 양발 목표와 무릎 방향만 기록한다.
골반 회전과 척추·팔에는 회전 수정이 없다. 이전 v2 자산과 Crunch 원본은 보존한다.
몸 이동은 Root Motion이 담당하며 수동 전진 Notify를 함께 사용하지 않는다.
손 판정은 몽타주 시간 0.61–0.81초, 재생 속도는 0.75다.

기능 검사:

- 출력된 골반·상체 회전의 바탕 대비 최대 차이는 약 0.004도였다.
- 타격 전후 제작 프레임에서 발 목표 오차는 최대 약 0.012cm였다.

### 2026-10-07 발걸음 축소 v2

사용자 영상에서 공격 뒤 양발을 다시 옮기는 동작이 과하게 보였다.
오른발의 주 디딤은 유지하고, 뒷발 보정은 이동 97→60cm(애니메이션 공간), 들기 11→2cm로 줄였다.
후딜에 넣었던 왼발 재전진과 오른발 재배치를 제거했다. 공격 후에는 디딘 자세를 유지한다.
기존 Root 이동 키, 펀치 키, 타격/FX Notify 시간은 유지했다.

Bake한 제작 프레임에서 발 목표 오차는 최대 약 0.000124cm, 후딜 발 위치 변화는 약 0.000107cm 이하였다.
이는 애니메이션의 발 목표 재현 검사이며 자연스러움의 합격 판정은 아니다.
테스트에서는 후딜에 발을 계속 들지 않는지, 뒷발 보정이 과하지 않은지,
마지막 대기 자세로 돌아가는 연결이 튀지 않는지 확인한다.

`Lvl_BossMotionLab`에서 L로 비교 방식을 바꿔 **오른발 디딤 → 왼손 · 1키 전용**을 선택하고 1을 누른다.
기본 제자리 모드의 1과 비교한다. H는 판정 표시, J는 거리 측정, R은 실험 배치 초기화다.

1. 오른발을 들고 옮기는 동작이 눈에 보이는가?
2. 오른발이 착지한 뒤 몸이 실리고 왼손이 나가는가?
3. 지지하는 왼발이 바닥 위를 미끄러지지 않는가?
4. 오른발이 착지한 다음 왼발이 풀리는가? 두 발이 동시에 미끄러지지 않는가?
5. 무릎이나 발목이 갑자기 돌아가지 않는가?
6. 기존 대기 자세로 돌아갈 때 튀거나 발이 끌리지 않는가?
7. 500cm와 550cm에서 실제 주먹이 닿는가? 보이지 않는 넓은 판정으로 대신 맞추지 않는가?

정상 속도 정면·측면에서 먼저 판단한다. 느린 재생은 문제가 발생한 구간을 찾는 데 사용한다.
피드백은 “착지 전 몸이 먼저 이동한다”, “오른발 착지에서 무릎이 튄다”처럼 구간과 현상을 알려주면 된다.

## 검증 범위

원본의 기본 FK 및 Crunch 전용 리그 왕복 Bake는 각각 비교 시점의 위치 차이 약 0.008cm 미만,
회전 차이 약 0.163도 이내였다. 이는 원본을 편집 경로로 옮기는 기능 검사다.
새 모션의 자연스러움이나 550cm 실제 타격이 검증됐다는 의미는 아니다.

새 모션의 기능 검사에서는 신규 Montage 재생과 약 204.91cm의 실제 캐릭터 전진을 확인했다.
**550cm에 멈춰 있는 플레이어에게는 피해가 발생하지 않았다. 550cm 도달 목표는 아직 미달이다.**
기능 검사의 통과 항목은 Montage 재생과 전진이며, 타격 거리 합격이 아니다.
이 시험의 기록은 `Saved/VibeUE/Scenarios/20261006T193542Z-EA21902C.json`이다.

제작 프레임의 발 목표 오차는 최대 약 0.00015cm였다. 이는 IK가 목표 위치를 재현하는지 검사한 값이다.
게임의 바닥 접촉, 무게감, 시작/끝 연결이 자연스럽다는 판단은 별도로 QA해야 한다.

이번 결과는 MotionLab 비교용 초안이다. 사용자의 동작 품질 QA 후 Arena의 Utility/GOAP에 확대한다.
