# Crunch 전진형 왼손: Control Rig 제작 및 QA

## 이번에 만드는 경험

왼발이 앞인 준비 자세에서 오른발을 앞으로 옮기고, 바닥을 짚으며 몸을 실어 왼손을 휘두른다.
기존 왼손의 공격 느낌을 출발점으로 삼는다. 전진형의 시작 거리 550cm 접촉은 목표이며,
몸의 이동량 205cm를 입력했다는 이유만으로 도달이나 모션 품질을 합격으로 판단하지 않는다.

## 제작 경로

현재 Unreal MCP → UE5.8 Control Rig / Sequencer → AnimSequence Bake → Montage / Notify → MotionLab.
Mixamo, 외부 모캡, 다른 캐릭터의 모션은 사용하지 않는다. 달리기 하체를 붙이는 방식도 사용하지 않는다.
원본 Crunch 시퀀스와 제자리 공격은 보존한다.

| 자산 | 역할 |
|---|---|
| `/Game/BossArena/Boss/Authoring/CR_Crunch_Attack` | 원본 자세용 FK, 발 목표, 무릎 방향, 다리 IK, Backwards Solve |
| `/Game/BossArena/Boss/Authoring/LS_Crunch_RightStep_LeftSwing` | 수정 가능한 공격 편집 원본 |
| `/Game/BossArena/Boss/Authoring/AS_Crunch_RightStep_LeftSwing` | Sequence에서 출력한 게임용 애니메이션 |
| `/Game/BossArena/Boss/Authoring/AM_Crunch_RightStep_LeftSwing` | 타격/FX Notify를 배치하는 Montage |

## 사용자가 확인할 것

### 2026-10-07 왼발 + 왼손 연결 v4 — 현재 모션랩 연결본

사용자 수정 지시: 지금 먼저 움직이는 오른발을 유지한다.
그다음 왼발을 내딛으면서 기존 왼손 공격이 이어지게 한다.
이번 작업은 애니메이션 연결에 한정하며 사거리·피해량·공격 판정 수치를 조정하지 않는다.

이전 버전은 오른발을 디디고 왼손을 휘두른 다음, 회복 구간에 왼발이 따라왔다.
이번에는 왼발 동작을 왼손 공격 구간으로 앞당겼다.
오른발의 위치·회전 키와 바탕의 골반 회전·팔 동작은 보존했다.
몸이 왼발과 함께 실리도록 기존 체중 이동의 시점도 맞췄다.
새로운 오른발 걸음이나 공격 뒤의 추가 발걸음을 넣지 않았다.

| 순서 | 동작 |
|---|---|
| 1 | 기존 오른발 디딤 |
| 2 | 왼발을 내딛는 동안 기존 왼손 휘두르기 |
| 3 | 디딘 자세를 유지하며 회복·대기 연결 |

**플레이 → L 세 번 → 1키**. 실행 이름은 `오른발 → 왼발 + 왼손 · 모션 연결 v4`.
실제 몽타주는 `AM_Crunch_LeftStep_WithPunch`다.
기본 제자리 모드의 1은 기존 제자리 공격이므로 새 버전과 구분한다.
J의 사거리 측정 모드를 켜면 거리 제한과 별개로 동작을 비교할 수 있다.

| 자산 | 역할 |
|---|---|
| `/Game/BossArena/Boss/Authoring/LS_Crunch_LeftStep_WithPunch` | v3 편집 파일의 별도 복제본. 왼발과 체중 이동 시점 수정 |
| `/Game/BossArena/Boss/Authoring/AS_Crunch_LeftStep_WithPunch` | 게임용 출력 |
| `/Game/BossArena/Boss/Authoring/AM_Crunch_LeftStep_WithPunch` | v3 몽타주 복제본. FX·판정 시간 유지, 출력 애니메이션만 교체 |

오른발의 저장된 채널 값이 이전 버전과 동일한지 확인했다.
제작 프레임에서 양발 목표 오차는 약 0.012cm 미만,
바탕 대비 골반·상체 회전 차이는 약 0.004도 미만이었다.
이는 수정 내용의 출력 검사이며 자연스러움의 합격 판정은 아니다.
사거리 시험은 이번 작업 범위에 포함하지 않았다.

사용자 QA는 **오른발 다음에 왼발과 왼손이 함께 나가는지**,
왼발이 공격 뒤에 늦게 따라오는 동작으로 보이지 않는지에 집중한다.
구현: `Tools/PolishCrunchLeftStep.py`. v3 편집 파일과 출력은 보존했다.

### 2026-10-07 원본 보존 v3 — 이전 연결본

이번 영상에는 `기본 제자리 · 몸 전진 없음`, `몸 전진 0cm`가 표시돼 있었다.
따라서 그 영상으로 v2 디딤 공격의 품질을 판단하지 않는다.

새 버전은 수정하지 않은 Crunch `Ability_Combo_01`을 복제한 별도 바탕에서 시작한다.
준비와 회복 시간을 조정하고, 시작과 마지막은 `Idle_Combat` 자세로 연결한다.
원본의 골반 회전·척추·팔 동작을 보존하며, 원본 위에 수정용 Control Rig 레이어를 얹는다.
팔 동작을 다시 만들거나 골반 회전을 척추로 옮기는 이전 처리는 사용하지 않는다.

| 구간 | 변경 내용 |
|---|---|
| 준비 | 대기 자세에서 원본 준비 자세로 연결한다. 원본의 골반 이동을 유지하며 몸 이동을 보정한다. |
| 주 디딤 | 오른발을 한 번 앞으로 내딛는다. 왼발은 바닥을 지지한다. |
| 왼손 공격 | 원본 골반 회전과 팔 동작을 유지한다. 지지 다리가 과하게 뻗지 않도록 몸을 잠깐 낮춘다. |
| 회복 | 왼발이 한 번 따라온다. 이후 추가 발걸음 없이 원본 대기 자세로 연결한다. |

몸을 낮추는 최대 보정은 애니메이션 공간 10cm, 배치 크기 1.3에서 약 13cm다.
몸 이동 205cm 전체가 주먹이 닿기 전에 일어나지는 않는다. 일부 이동은 뒷발이 따라오는 회복 구간에 있다.
따라서 총 이동 205cm를 사거리 증가 205cm로 해석하면 안 된다.

확인 방법: **PIE 시작 → L 세 번 → 오른발 디딤 모드 → 1**.
기본 제자리 모드의 1은 기존 모션이다. 실제 실행된 새 몽타주는
`AM_Crunch_LeftSwing_OriginalStep`, 행동 이름은 `오른발 디딤 → 왼손 · 원본 보존 v3`다.
우선 가까운 배치에서 발·골반·주먹이 연결되는지 확인한다.

| 새 자산 | 역할 |
|---|---|
| `/Game/BossArena/Boss/Authoring/AS_Crunch_LeftSwing_OriginalBase` | Crunch 원본을 복제한 바탕. 준비·회복 연결과 시간만 조정 |
| `/Game/BossArena/Boss/Authoring/CR_Crunch_OriginalStep` | 기존 리그의 별도 복제본 |
| `/Game/BossArena/Boss/Authoring/LS_Crunch_LeftSwing_OriginalStep` | 원본 바탕과 수정 레이어를 분리한 편집 파일 |
| `/Game/BossArena/Boss/Authoring/AS_Crunch_LeftSwing_OriginalStep` | 게임용 출력 |
| `/Game/BossArena/Boss/Authoring/AM_Crunch_LeftSwing_OriginalStep` | FX 및 손 접촉 판정 연결 |

수정 레이어에는 Root, 골반의 작은 위치 보정, 양발 목표와 무릎 방향만 기록한다.
골반 회전과 척추·팔에는 회전 수정이 없다. 이전 v2 자산과 Crunch 원본은 보존한다.
몸 이동은 Root Motion이 담당하며 수동 전진 Notify를 함께 사용하지 않는다.
손 판정은 몽타주 시간 0.61–0.81초, 재생 속도는 0.75다.

기능 검사:

- 출력된 골반·상체 회전의 바탕 대비 최대 차이는 약 0.004도였다.
- 타격 전후 제작 프레임에서 발 목표 오차는 최대 약 0.012cm였다.
- 마지막 자세의 주요 관절 위치는 원본 대기 자세와 약 0.002cm 미만 차이였다.
- 실제 PIE에서 새 몽타주 재생과 약 203.57cm 전진을 확인했다.
- 400cm 및 550cm 접촉 시험 모두 피해 0이었다. **550cm 목표 사거리는 미달이며, 400cm도 이번 시험에서는 맞지 않았다.**
- 비교용 모션의 자연스러움은 사용자 QA 대상이다. Arena의 Utility/GOAP에는 아직 확대하지 않았다.

시나리오: `20261007T080017Z-E92FDA31`(550cm), `20261007T080413Z-50BD309E`(400cm).
두 시나리오의 합격 항목은 재생·전진이며 사거리 합격이 아니다.
구현 경로: `Tools/AuthorCrunchOriginalStep.py`. 플레이 검사: `Tools/TestCrunchOriginalStep.py`.

다음 수정에서는 사용자 동작 QA와 별개로 타격 순간의 실제 전진량을 확인해야 한다.
사거리를 맞추려면 원본의 체중 이동을 보존하면서 디딤·주먹의 시점을 함께 조정해야 한다.
넓은 보이지 않는 판정으로 부족한 거리를 보충하지 않는다.

### 2026-10-07 발걸음 축소 v2

사용자 영상에서 공격 뒤 양발을 다시 옮기는 동작이 과하게 보였다.
오른발의 주 디딤은 유지하고, 뒷발 보정은 이동 97→60cm(애니메이션 공간), 들기 11→2cm로 줄였다.
후딜에 넣었던 왼발 재전진과 오른발 재배치를 제거했다. 공격 후에는 디딘 자세를 유지한다.
기존 Root 이동 키, 펀치 키, 타격/FX Notify 시간은 유지했다.

Bake한 제작 프레임에서 발 목표 오차는 최대 약 0.000124cm, 후딜 발 위치 변화는 약 0.000107cm 이하였다.
이는 애니메이션의 발 목표 재현 검사이며 자연스러움의 합격 판정은 아니다.
테스트에서는 후딜에 발을 계속 들지 않는지, 뒷발 보정이 과하지 않은지,
마지막 대기 자세로 돌아가는 연결이 튀지 않는지 확인한다.

`Lvl_BossMotionLab`에서 L로 비교 방식을 바꿔 **오른발 디딤 → 왼손 · 1키 전용**을 선택하고 1을 누른다.
기본 제자리 모드의 1과 비교한다. H는 판정 표시, J는 거리 측정, R은 실험 배치 초기화다.

1. 오른발을 들고 옮기는 동작이 눈에 보이는가?
2. 오른발이 착지한 뒤 몸이 실리고 왼손이 나가는가?
3. 지지하는 왼발이 바닥 위를 미끄러지지 않는가?
4. 오른발이 착지한 다음 왼발이 풀리는가? 두 발이 동시에 미끄러지지 않는가?
5. 무릎이나 발목이 갑자기 돌아가지 않는가?
6. 기존 대기 자세로 돌아갈 때 튀거나 발이 끌리지 않는가?
7. 500cm와 550cm에서 실제 주먹이 닿는가? 보이지 않는 넓은 판정으로 대신 맞추지 않는가?

정상 속도 정면·측면에서 먼저 판단한다. 느린 재생은 문제가 발생한 구간을 찾는 데 사용한다.
피드백은 “착지 전 몸이 먼저 이동한다”, “오른발 착지에서 무릎이 튄다”처럼 구간과 현상을 알려주면 된다.

## 검증 범위

원본의 기본 FK 및 Crunch 전용 리그 왕복 Bake는 각각 비교 시점의 위치 차이 약 0.008cm 미만,
회전 차이 약 0.163도 이내였다. 이는 원본을 편집 경로로 옮기는 기능 검사다.
새 모션의 자연스러움이나 550cm 실제 타격이 검증됐다는 의미는 아니다.

새 모션의 기능 검사에서는 신규 Montage 재생과 약 204.91cm의 실제 캐릭터 전진을 확인했다.
**550cm에 멈춰 있는 플레이어에게는 피해가 발생하지 않았다. 550cm 도달 목표는 아직 미달이다.**
기능 검사의 통과 항목은 Montage 재생과 전진이며, 타격 거리 합격이 아니다.
이 시험의 기록은 `Saved/VibeUE/Scenarios/20261006T193542Z-EA21902C.json`이다.

제작 프레임의 발 목표 오차는 최대 약 0.00015cm였다. 이는 IK가 목표 위치를 재현하는지 검사한 값이다.
게임의 바닥 접촉, 무게감, 시작/끝 연결이 자연스럽다는 판단은 별도로 QA해야 한다.

이번 결과는 MotionLab 비교용 초안이다. 사용자의 동작 품질 QA 후 Arena의 Utility/GOAP에 확대한다.
